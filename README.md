# portage-overlay

A small personal Gentoo overlay.

## Packages

| Package | Description |
| --- | --- |
| `www-nginx/nginx-otel-module` | NGINX native OpenTelemetry (OTLP/gRPC) tracing module, built against Gentoo's own `net-libs/grpc` and `dev-cpp/opentelemetry-cpp` rather than upstream's vendored FetchContent copies |

## Using it

With `app-eselect/eselect-repository`:

```sh
eselect repository add portage-overlay git https://github.com/sonOfRa/portage-overlay.git
emaint sync -r portage-overlay
```

Or by hand, as `/etc/portage/repos.conf/portage-overlay.conf`:

```ini
[portage-overlay]
location = /var/db/repos/portage-overlay
sync-type = git
sync-uri = https://github.com/sonOfRa/portage-overlay.git
auto-sync = yes
```

The overlay sets `masters = gentoo`, so the ::gentoo repo must be present.

## Development

Manifests are thin (`thin-manifests = true`), so they contain only `DIST` lines.
Regenerate them from the package directory:

```sh
cd www-nginx/nginx-otel-module
pkgdev manifest
```

and run QA over the whole repo before pushing:

```sh
pkgcheck scan
```

Both tools come from `dev-util/pkgdev` on Gentoo. They are pure Python and also
install from PyPI (`uv pip install pkgdev`) on non-Gentoo systems, where they need
a local ::gentoo checkout for the eclasses and an `etc/portage` containing
`repos.conf`, `make.conf` and a `make.profile` symlink. Note that pkgcore locates
that config by walking up from `sys.prefix`, not via `PORTAGE_CONFIGROOT`.

`metadata/md5-cache/` is generated by these tools and is not tracked.
